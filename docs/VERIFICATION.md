# Verification

Everything on this page is regenerated by

```bash
python reproduce.py --only verification --only consistency --only benchmark
```

which writes [`results/verification.txt`](../results/verification.txt),
[`results/shared_inventory_consistency.txt`](../results/shared_inventory_consistency.txt) and
[`results/lca_implementation_benchmark.txt`](../results/lca_implementation_benchmark.txt). Where
this page and a generated file disagree, the generated file is authoritative.

> **Verification is not validation.** Everything here asks whether the software is
> self-consistent and whether independent implementations of it agree. Nothing here says the
> model is *right*. Accuracy is [VALIDATION.md](VALIDATION.md), and it is much weaker evidence.

## The scenario suite

All three checks run over one set, so they describe the same population:
`algametrix.paper.suite`. 34 members, **26 structurally distinct** — several members build an
identical `Scenario` by different routes (a template and the reconstruction wrapping it; an
archetype and its template) and are counted once, so the evidence base is not inflated.

| Axis | Distinct scenarios |
|---|---:|
| phototrophic / heterotrophic | 22 / 4 |
| CO₂ gas / NaHCO₃ carbon source | 19 / 3 |
| area basis / volume basis | 22 / 4 |
| continuous / batch | 24 / 2 |
| with drying / without | 14 / 12 |
| with downstream extraction | 5 |
| with multi-product allocation | 5 |
| with explicit media / utility line items | 5 |

Provenance: 15 study reconstructions, 8 shipped templates, 3 sensitivity archetypes and 8
variants that exist to reach code paths the others do not (bicarbonate feed, batch scheduling,
electric drying, no drying, seasonally heated pond, and each biogenic-carbon convention).

## 1. Construction identities and physical admissibility

Two families, reported separately because they are not equally strong evidence.

### 1a. Construction identities

Each restates an inventory field as a closed form of the scenario, written in `verification.py`
independently of `inventory.py`, and compares the two:

- CO₂ fixed ÷ M(CO₂)/M(C) = biomass carbon; inorganic carbon supplied × utilization = fixed
  (phototrophic);
- substrate × mass yield = gross biomass (heterotrophic);
- N and P supplied × uptake = nutrient in biomass; supplied = assimilated + emitted.

**These hold by construction and cannot fail for any parameter values.** `build_inventory`
derives the nitrogen supply as `org.nitrogen × gpp / uptake`, so `supply × uptake =
org.nitrogen × gpp` is an identity; the residual measures floating-point round-off. They are
worth running — they detect a change to `inventory.py` that is not mirrored here — but they are
**specification tests, not conservation results**, and the tiny residuals must not be read as
evidence that mass is conserved. Earlier versions of this page and of the reports called them
carbon, nitrogen and phosphorus *balances*, which claimed more than they test.

**26/26 PASS, maximum relative residual 1.2 × 10⁻¹⁶ — a statement about the implementation,
not about the physics.**

### 1b. Physical admissibility

Inequalities a scenario can genuinely violate:

- **Composition** — biomass C + N + P ≤ 1 kg per kg dry mass;
- **Fractions** — harvesting recovery, nutrient uptake and carbon utilization all in (0, 1];
- **Heterotrophic carbon feasibility** — the carbon incorporated into biomass cannot exceed the
  carbon supplied by the substrate. This is the elemental constraint the identity above does
  *not* test, because that identity never mentions carbon. The remainder is respired and is
  reported as `biogenic_co2_respired_per_kg`;
- **Product mass** — downstream products never sum to more than the biomass fed;
- **Scale invariance** — per-kg intensities unchanged when the plant scale is doubled
  (continuous mode, where this is mathematically required).

**26/26 PASS.** Across the four heterotrophic scenarios, 51–54 % of the substrate carbon is
incorporated into biomass and the remaining 2.0–2.2 kg CO₂-eq per kg product is respired.

> Respired carbon is **reported, not summed**. Substrate carbon enters as biogenic carbon and
> leaves as biogenic CO₂, so under the biogenic 0/0 convention both sides are excluded from the
> GWP — the same treatment `substrate_co2_supplied_per_kg` already receives. Counting it would
> raise the heterotrophic gross GWP by 27–86 % and would break agreement with the published
> values the blind GWP reproductions match, which is evidence that those sources use the same
> convention.

## 2. Shared-inventory consistency

This is the check behind the claim that TEA and LCA "read the same physical inventory".

### What it is

`run_scenario` builds one `Inventory` and hands the **same object** to `run_tea` and `run_lca`.
Agreement is therefore an **architectural invariant**, guaranteed by the call graph rather than
discovered by experiment. It is measured anyway, for three reasons:

1. **Sharing an object does not guarantee both analyses read the same field of it.** The
   inventory carries both `co2_supply_per_kg` (gas fed to the culture) and `co2_fixed_per_kg`
   (carbon actually incorporated); they differ by the carbon-utilization efficiency, both are
   plausible, and pricing one while characterizing the other is an error that object identity
   does nothing to prevent.
2. The quantities are recovered from the **published results**, so the check also covers
   everything between the inventory and the reported number — overheads, product allocation,
   the functional unit.
3. It turns a design claim into a number, and it keeps holding: it runs on every commit.

### How a quantity is recovered

Both analyses are exactly affine in their own coupling coefficient, so the physical quantity
*is* the derivative, and a central difference recovers it:

```
q_TEA(k) = [ d(production cost) / d(unit price of k) ] / (1 + overhead_frac)
q_LCA(k) =   d(gross GWP)       / d(GWP factor of k)
```

Both are in physical units of *k* per kg dry biomass, read off two different result objects.
The only non-physical term is `overhead_frac`, because overhead is *defined* in
[`tea.py`](../src/algametrix/tea.py) as a multiple of the priced flows; dividing it out leaves
a physical quantity. Water and land carry no characterization factor and are recovered
directly.

The two recoveries each rebuild an inventory from the scenario rather than sharing one object.
That is deliberate and is the stronger test: `build_inventory` is a pure function of the
scenario, so the two inventories are identical by construction, and what the comparison
isolates is whether the two analyses **read the same fields** and report on the same basis.

### What is checked

| Flow classes | Structural checks |
|---|---|
| electricity, heat, CO₂ supply, NaHCO₃, nitrogen, phosphorus, organic substrate, water, extraction solvent, every explicit `Material` and `Utility` | functional unit (TEA's cost denominator == LCA's reference flow); land (area capitalised == area occupied); allocation (cost share == impact share, per product) |

Plus a **propagation test**: harvesting recovery is moved by −10 % and the whole recovery is
repeated, confirming both analyses follow the change together and that the flows genuinely move,
so the check is not vacuous.

### Result

**26 scenarios, 162 flow comparisons, all PASS.** Maximum relative TEA–LCA discrepancy
**1.2 × 10⁻¹³**; maximum gap between a recovered quantity and the inventory field itself
**1.2 × 10⁻¹³**. The residual is round-off in the two evaluations of the central difference and
is bounded by double precision.

### The counter-example

The same file carries a controlled demonstration of what the invariant buys. Duplicated
inventories are emulated by giving TEA and LCA their own copy of the scenario, and the
harvesting recovery (0.90 → 0.765) is updated **in the TEA copy only**:

| | shared inventory | duplicated inventories |
|---|---|---|
| max TEA–LCA flow disagreement | 3 × 10⁻¹⁴ | **15.0 %** |
| reported production cost | 18.89 /kg | 18.89 /kg |
| reported gross GWP | 8.32 kg CO₂-eq/kg | 7.61 kg CO₂-eq/kg (**−8.5 %**) |

The cost is identical because the economic copy received the edit in both arms. The whole error
is in the environmental result, the pair is still reported as a matched
economic–environmental result, and no internal check on the LCA alone would find it: the stale
inventory is perfectly self-consistent, it is simply a different plant.

**This is a failure mode demonstrated on this engine against itself. No other software was
inspected, and none is implicated.**

## 3. Independent LCA implementation benchmark

[`algametrix.paper.matrixlca`](../src/algametrix/paper/matrixlca.py) recomputes every impact
from the matrix formalism used by matrix-based LCA software:

```
A s = f        g = B s        h = C g
```

It shares **no code** with [`lca.py`](../src/algametrix/lca.py) and never reads an `Inventory`:
both matrices are assembled from the primitive scenario parameters, so agreement tests
[`inventory.py`](../src/algametrix/inventory.py) as well. The foreground is a genuine
multi-stage chain (cultivation → harvesting → drying → extraction) in which the harvesting
recovery is an **off-diagonal transfer coefficient** in **A**, solved by LU factorisation.
Which process carries the biogenic-uptake elementary flow *is* the accounting convention.

Two honest caveats: **C** is close to the identity, because AlgaMetrix ships already-characterized
cradle-to-gate factors; **A** is block-triangular, because the background is a cut-off
unit-process system.

**26 scenarios × 9 indicators = 234 comparisons; maximum relative difference 2.4 × 10⁻¹⁵.**
Technosphere condition numbers 18–1.3 × 10⁵.

### Brightway cross-check (optional)

The same **A**, **B** and **C** matrices handed to `bw2calc` 2.5.0: **182 comparisons, maximum
relative difference 4.9 × 10⁻¹⁵** ([`results/brightway_crosscheck.txt`](../results/brightway_crosscheck.txt)).

Not part of `reproduce.py` — `bw2calc` pulls in around thirty packages the engine does not need:

```bash
python -m venv .bwenv
.bwenv/bin/pip install bw2calc numpy pyyaml pandas    # Windows: .bwenv\Scripts\pip
.bwenv/bin/python scripts/brightway_crosscheck.py
```

Brightway is not the primary benchmark because its value lies in coupling a model to a licensed
background database, which this repository does not ship. Over a hand-built foreground with the
same aggregated factors it exercises the same linear algebra behind a much larger dependency
surface.

## 4. What is *not* verified

1. **The TEA has no independent re-implementation.** The SuperPro comparisons in
   [VALIDATION.md](VALIDATION.md) are external validation against published vendor reports, not
   an implementation benchmark.
2. **The characterization factors are not verified**, only the arithmetic applied to them —
   which is why **C** is close to the identity. See the LCIA-factor limitation in the README.
3. **Nothing dynamic is verified**, because nothing dynamic is modelled: the physical system is
   a single steady operating point.
